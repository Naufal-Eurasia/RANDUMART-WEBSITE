Panduan Update dan Deploy Website Menggunakan VS Code, GitHub, dan Hostinger :

Langkah 1: Periksa Perubahan Project

Setelah selesai melakukan perubahan pada website di VS Code, buka Terminal dan jalankan perintah berikut untuk melihat file yang telah berubah:

git status

Pastikan semua perubahan yang telah dilakukan muncul pada daftar perubahan Git.

Langkah 2: Build Project

Jika masih berada di dalam folder dist, kembali ke folder utama project terlebih dahulu:

cd ..

Kemudian lakukan proses build untuk menghasilkan file website terbaru:

npm run build

Perintah ini akan membuat atau memperbarui folder dist yang berisi hasil build website siap deploy.

Langkah 3: Masuk ke Folder Build

Setelah proses build selesai, masuk ke folder dist:

cd dist

Periksa kembali status Git:

git status
Langkah 4: Tambahkan Perubahan ke Git

Tambahkan seluruh file yang telah diperbarui:

git add .

Kemudian buat commit baru dengan pesan yang sesuai:

git commit -m "Update Website"

Pesan commit dapat disesuaikan dengan jenis perubahan yang dilakukan, misalnya:

git commit -m "Perbaikan Tampilan Mobile"

atau

git commit -m "Update Data Program UMKM"
Langkah 5: Verifikasi Status Git

Periksa kembali status repository:

git status

Jika tidak ada perubahan yang tertinggal, maka repository sudah siap untuk dikirim ke GitHub.

Langkah 6: Push ke GitHub

Kirim seluruh perubahan ke repository GitHub:

Jika menggunakan branch master:

git push origin master

Jika menggunakan branch main:

git push origin main

Pastikan proses push berhasil tanpa error.

Langkah 7: Verifikasi di GitHub

Buka repository GitHub dan lakukan refresh halaman.

Pastikan commit terbaru yang telah dibuat muncul pada daftar commit repository.

Langkah 8: Verifikasi Website di Hostinger

Karena website telah terhubung dengan GitHub melalui proses deployment, lakukan refresh pada website, Pastikan seluruh perubahan yang telah dilakukan di VS Code sudah tampil pada website yang dihosting di Hostinger.

### Bagian 1: Menghubungkan Hostinger & GitHub (Menit 12.03 - 13.28)

Video tersebut menjelaskan cara menghubungkan repository GitHub ke Hostinger Shared Hosting dan mengaktifkan **Auto Deployment** menggunakan Webhook.

#### Langkah A: Generate SSH Key & Hubungkan GitHub

1. **Ambil SSH Key dari Hostinger:**
* Buka hPanel Hostinger > Masuk ke menu **Hosting** > Pilih Domain Anda.
* Buka menu **Advanced** > klik **Git**.
* Di bagian atas, temukan dan **copy SSH Key** yang disediakan oleh Hostinger.


2. **Tambahkan Deploy Key ke Repository GitHub:**
* Buka repository GitHub project Anda.
* Pergi ke **Settings** > **Deploy keys** (di bilah navigasi kiri).
* Klik **Add deploy key**.
* **Title**: Masukkan nama bebas (contoh: `Hostinger Deploy Key`).
* **Key**: Paste SSH Key dari Hostinger tadi.
* Centang opsi **Allow write access** (opsional/jika diperlukan).
* Klik **Add key**.



#### Langkah B: Clone Repository di Hostinger

1. Kembali ke hPanel Hostinger pada halaman **Git**.
2. Isi formulir **Create a New Repository**:
* **Repository SSH URL**: Ambil URL SSH dari GitHub (format: `git@github.com:username/repository.name.git`).
* **Branch**: Isikan `main` atau `master` sesuai branch target Anda.
* **Directory**: Biarkan kosong agar ter-deploy langsung ke folder utama `public_html` (pastikan folder `public_html` di File Manager sudah dibersihkan/kosong terlebih dahulu).


3. Klik **Create** lalu klik tombol **Deploy**.

#### Langkah C: Mengaktifkan Auto-Deployment (Webhook) (Menit 11.08 - 12.03)

1. Di halaman Git Hostinger, gulir ke bawah ke tabel *Deployed Repositories*.
2. Klik tombol **Auto Deployment** / **Webhook**.
3. Copy **Webhook URL** yang muncul.
4. Buka GitHub > Repository Anda > **Settings** > **Webhooks** > **Add webhook**.
5. Paste Webhook URL ke kolom **Payload URL**.
6. Set **Content type** ke `application/json`.
7. Simpan dengan menekan **Add webhook**.
*(Sekarang setiap kali Anda `git push` folder build ke branch utama, Hostinger akan otomatis menarik perubahan terbaru)*

### Bagian 2: Penyesuaian Beda Akun GitHub dan Hostinger

Jika **Akun GitHub pemilik project** berbeda dengan **Akun Hostinger**:

1. **Deploy Keys per Repository (Paling Direkomendasikan):**
* Anda **TIDAK perlu** menggabungkan atau menyamakan akun.
* Ambil SSH Key dari akun Hostinger tempat website disewa, lalu masukkan SSH Key tersebut ke **Settings > Deploy keys** pada repository di akun GitHub pemilik project.
* Cara ini aman dan langsung bekerja tanpa mengubah akun GitHub utama.


2. **Repository Publik vs Privat:**
* Jika repository diatur ke **Public**, Anda dapat menggunakan HTTP/HTTPS Repository URL langsung di Hostinger tanpa perlu menambahkan SSH Key.
* Jika repository **Private**, gunakan SSH URL (`git@github.com:...`) dan wajib menambahkan Deploy Key di GitHub.

### Bagian 3: Penyesuaian Khusus Stack Next.js + Neon + Prisma + Tailwind

Video tutorial di atas memperagakan deploy **React/Vite (Static Export)** ke *Shared Hosting* Hostinger. Karena Anda menggunakan Next.js dengan Prisma & Database (Neon/PostgreSQL), ikuti penyesuaian wajib berikut:

#### 1. Konfigurasi Next.js Static Export (`next.config.js` / `next.config.mjs`)

Shared Hosting Hostinger **tidak mendukung Node.js server berjalan terus-menerus** (layanan SSR/Server Side Rendering membutuhkan VPS Server). Oleh karena itu, Next.js harus di-export menjadi file statis (`out` folder):

```javascript
/** @type {import('next').NextConfig} */
const nextConfig = {
  output: 'export', // Menghasilkan folder 'out' saat npm run build
  images: {
    unoptimized: true, // Wajib diaktifkan untuk static export
  },
};

module.exports = nextConfig;

```

#### 2. Penyesuaian Prisma & Database Neon

* Karena hasil build berstatus *Static Site*, server-side route bawaan Next.js (`/api/...`) **tidak akan berjalan di Shared Hosting**.
* **Solusi untuk Database/Prisma:**
1. Pastikan `npx prisma generate` dan migrasi database Neon sudah dijalankan saat pengembangan lokal/sebelum proses build.
2. Panggil API Neon secara eksternal (misal lewat Serverless Functions seperti Vercel API / Cloudflare Workers) **ATAU** gunakan paket koneksi langsung via Client-side jika memungkinkan secara arsitektur.
3. Kelola koneksi string database Neon di environment lokal Anda.



#### 3. Update Script Build (`package.json`)

Sesuai workflow di VS Code, ubah skrip build agar menghasilkan folder hasil kompilasi:

```json
"scripts": {
  "build": "prisma generate && next build"
}

```

#### 4. Langkah Deploy Folder Build Next.js

Berbeda dengan Vite yang menghasilkan folder `dist`, Next.js dengan `output: 'export'` akan menghasilkan folder **`out`**:

1. Jalankan build di lokal:
```bash
npm run build

```


2. Masuk ke folder **out**:
```bash
cd out

```


3. Lakukan inisialisasi Git dan Push dari dalam folder `out`:
```bash
git init
git add .
git commit -m "Build Next.js Website"
git branch -M main
git remote add origin git@github.com:USERNAME/REPO-BUILD.git
git push -u origin main --force

```


4. Arahkan repository Git di Hostinger ke repo/branch yang berisi isi folder `out` tersebut agar file `index.html` terbaca langsung di `public_html` Hostinger.
